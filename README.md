## 为什么做这个

X 网页端有不少操作要绕路，比如：

- 长文和帖子下面混着大量塞满 emoji 的引流号、色情引流号回复；
- 在几千字的长文下面回复，要往下滚好几屏才到输入框；
- 想在新帖里引用自己以前的帖子或长文，要另开一个标签页去找链接；
- 在自己的「正在关注」列表里看不出谁没回关，只能一个个点进主页确认。

oh-my-x 在星川（[@star_flow_ai](https://x.com/star_flow_ai)）的 [X Focus](https://x.com/star_flow_ai/status/2097583620936585339) 基础上开发，加入了作者自己和 X 上朋友们提出的需求。用不上的功能都可以在设置里关掉。

## 安装

### 方式一：下载发行包（推荐，不需要开发环境）

1. 在 [Releases 页面](https://github.com/longhaiqwe/oh-my-x/releases/latest) 下载 `oh-my-x-chrome-mv3.zip`
2. 解压，得到 `chrome-mv3` 文件夹。把它放在一个固定位置，以后不要挪动
3. 打开 `chrome://extensions`（Edge 同样适用），开启右上角的「开发者模式」
4. 点「加载已解压的扩展程序」，选择 `chrome-mv3` 文件夹

**升级**：解压新版本，用里面的文件覆盖原来的 `chrome-mv3` 文件夹，再到 `chrome://extensions` 点 oh-my-x 卡片上的刷新按钮。

> [!WARNING]
> 换文件夹位置，或点「移除」后重新加载，Chrome 会当成一个新扩展，设置、词库和拦截记录都会清空。

### 方式二：从源码构建

需要 Node.js 24（自带 npm）。

```bash
git clone https://github.com/longhaiqwe/oh-my-x.git
cd oh-my-x
npm install
npm run build
```

然后在 `chrome://extensions` 开启「开发者模式」，点「加载已解压的扩展程序」，选择 `oh-my-x/build/chrome-mv3/`。

### 方式三：Chrome 网上应用店

[从 Chrome 网上应用店安装 oh-my-x](https://chromewebstore.google.com/detail/ehnedndgpdkclhddhgdkdadhbiafaend)

### 01 界面与阅读

#### 时间线宽度

在 600 到 800 像素之间调整主时间线的宽度，也就是下图箭头标出的那一段。

<p align="center">
  <img src="docs/images/layout-timeline-width.webp" width="850" alt="时间线宽度示意" />
</p>

#### 隐藏右侧边栏、隐藏发帖按钮

两个开关，打开即隐藏。右侧边栏包括搜索、推荐关注和趋势；发帖按钮隐藏后可以按 `N` 发帖，搜索可以从左侧「探索」进入。屏幕较小时隐藏这两块，时间线能占更多空间。

<p align="center">
  <img src="docs/images/layout-hide-sidebar.webp" width="850" alt="隐藏右侧边栏和发帖按钮后的页面" />
</p>

#### 导航栏按钮与文字

探索、通知、聊天、Grok、Premium、历史、文章、个人资料、更多、X Money 共 10 个按钮可以分别隐藏。被 X 收进「更多」菜单的入口，也会在菜单里一起隐藏。导航文字可设为从不、悬停或始终显示。

Premium 优先保留 X 原生入口（中文界面可能显示为「订阅」），并清理插件添加的重复按钮；仅在缺少原生入口且能获取页面图标时尝试补建。

另有 Radar 和「灵感」（创作者工作室里的高互动帖子排行）两个按钮，X 的导航栏里没有，由插件添加，默认关闭；Radar 需要 Premium+。打开后显示在「个人资料」上方，点击时不重新加载页面。窗口较矮时导航栏会多出这两项的高度，要滚动左栏才能看到底部的账号按钮。

<p align="center">
  <img src="docs/images/layout-nav-buttons.webp" width="850" alt="设置里的导航栏按钮（❶）和页面左侧导航栏（❷）一一对应" /><br>
  <sub>设置里的按钮（❶）和页面左侧导航栏（❷）一一对应</sub>
</p>

#### 长文目录

在长推文、长文阅读页和长文编辑器侧边，提取一级和二级标题生成目录，点击跳到对应位置。能识别 Markdown 标题（`#`、`##`）、「一、」「第一章」这类中文序号、「1.」「(1)」这类数字序号，以及整段加粗的段落。

<p align="center">
  <img src="docs/images/layout-article-toc.webp" width="850" alt="长文页右侧的目录" />
</p>

#### 回看

在「界面 → 阅读 → 回看」开启自动记录后，会保存首页「为你推荐」和「正在关注」中实际显示的推文。默认关闭；推文可见高度达到自身一半或视口高度的 40%（取较小值）时记录，广告、详情页、个人主页及被过滤隐藏的内容不记录。

- 从 X 左侧导航的「回看」、插件设置或 `Alt+Shift+R` 打开。窄屏下可从「更多」菜单进入。
- 搜索正文、作者、引用内容，按图片、视频、引用和转帖筛选。记录按首次看到的时间排列，同一条推文再次出现不会重复新增。
- 原帖在新标签页打开，保留当前首页的位置。暂停记录后仍可查阅；清空仅删除当前账号的回看记录及其图片文字索引。
- 可选「识别图片文字」使用本机 OCR，不调用 AI 服务，也不需要 API Key。首次启用会请求图片及识别数据来源的访问权限，并下载语言数据；关闭后停止识别和图片文字检索。
- 搜索兼容中英文混排空格，例如「AI 工具」可用「AI工具」查找；类型筛选会在刷新后保留。OCR 包括图片、视频封面和链接缩略图，按浏览器语言选择中、英、日、韩识别数据；单张图片失效时跳过并继续。
- 数据按账号保存在扩展本地 IndexedDB，每个账号最多 3000 条、约 20 MB；达到任一上限后移除最早记录。保存的是媒体地址，不保证离线时图片可用。X Pro 不采集。

#### 搜索默认「最新」

X 的搜索默认打开「热门」，按互动量排列，会混进几个月前的帖子。打开这个开关后，新的搜索（换了搜索词，或从别的页面进来）打开「最新」标签，按发布时间排列。话题标签页同样处理。在同一个搜索里点回「热门」，这个搜索词之后保持「热门」。

#### 搜索筛选条

搜索结果页和话题标签页的标签下面多一排筛选，不用记搜索语法：

| 筛选 | 选项 | 写进搜索词的语法 |
|------|------|------|
| 时间 | 24 小时内 / 7 天内 / 30 天内 | `within_time:24h` / `7d` / `30d` |
| 点赞数 | 至少 10 / 100 / 1000 赞 | `min_faves:10` 等 |
| 图片视频 | 带图片 / 带视频 / 带图片或视频 | `filter:images` / `filter:videos` / `filter:media` |
| 只看原帖 | 开 / 关 | `-filter:replies` |
| 只看关注的人 | 开 / 关 | 地址参数 `pf=on` |

选择后改写搜索词重新搜索，搜索框里能看到并继续修改。搜索框里自己写的同类语法（如 `min_faves:500`）会显示在对应的下拉框里。「用户」「列表」标签不显示筛选条。

没有语言筛选：X 把长文帖的语言记为「无文字」，用 `lang:zh` 会把中文长文一起排除。需要时可以在搜索框里自己加 `lang:zh`，筛选条会原样保留。

#### 问 Grok

在搜索框里输入文字后，下拉列表里「搜索“…”」下面多一项「问 Grok」。点一下打开 Grok 页面并填好这段文字，X 会弹出确认框，点 Send 后 Grok 才收到问题。

从属开关「回车问 Grok」（默认关闭）：打开后在搜索框按回车直接打开 Grok，不做普通搜索。要普通搜索时点下拉里的「搜索“…”」；用方向键选中下拉里的项目后按回车，仍按 X 原来的方式。

#### AI 转搜索语法

下拉列表里还有一项「用 AI 转成搜索语法」：用你在「设置 → AI 服务」配置的模型，把大白话转成 X 的搜索语法，再用 X 自己的搜索去搜。提示词里给模型的示例：今天是 2026-10-23 时，「上周关于 Claude、点赞过千的中文帖」转成 `Claude lang:zh min_faves:1000 since:2026-10-16`；实际结果取决于你用的模型。结果是 X 原生的帖子列表，可以切「最新」、点赞、回复。

需要先配置 AI 服务；没配置或没授权时，这一项下面显示报错和「打开 AI 服务设置」。点这一项时，搜索框里的文字会发给你配置的 AI 服务。

### 02 内容过滤

<p align="center">
  <img src="docs/images/module-filter.webp" width="420" alt="设置弹窗的「过滤」标签" />
</p>

#### 垃圾回复过滤

按规则给推文详情页里的回复打分，得分达到隐藏阈值（默认 55，可在 20 到 150 之间调整）的回复会被隐藏。只处理推文详情页的对话，首页等时间线不处理。

**9 条检测规则**，可逐条开关：

| 规则 | 检测内容 | 默认分 |
|------|---------|--------|
| 营销昵称 | 昵称含「点击主页 / 同城 / 约会 / 固炮」等词 | +40 |
| Emoji 占比 | 回复中 emoji 超过文字的一半 | +20 |
| 评论过短 | 正文少于 8 个字符；英文等按词算，少于 2 个词 | +10 |
| 随机用户名 | 用户名像随机的字母加数字组合（特征明显时最高 +25） | +10 |
| 垃圾词库 | 回复命中词库中的词（多词累加，最高 65） | +35 |
| 纯 Emoji 评论 | 去掉 emoji 后内容为空 | +40 |
| 装饰昵称 | 昵称含 2 个以上 emoji | +15 |
| 重复字符 | 同一字符连续重复 4 次以上（如「哈哈哈哈」） | +20 |
| 矩阵引流 | 用「看@」「主页@」「👉@」「visit @」等引导到其他账号，或结尾 @ 账号后跟几个随机字符或表情 | +20 |

- **垃圾词库**：第一个命中的词 +35，每多命中 1 个不同的词再加 15，最高 65。和正文屏蔽词分开管理。新安装时按界面语言写入默认词：中文界面写中文词库，英文界面写英文词库（如 "check my bio"、"dm me"）；「补充默认词」「恢复默认」也按当前界面语言。
- **选词**：推文右上角「更多」按钮旁的选词按钮，可以从昵称和回复内容里点选词语加入词库。
- **调试模式**：在每条回复下显示得分和命中的规则，用来调整阈值和词库。

#### AI 判断进度

评论 AI 判断支持流式显示：模型每返回一条完整评分，就立即更新对应回复，无需等待整批完成。顶部显示「AI 判断中 · 3/20」和加载动画，数字表示本页已完成数 / 当前已完成与等待结果的总数；新回复进入判断队列时总数会变化。

已经完成的结果会逐条缓存。若后续超时或连接中断，已有结果保留，重试只处理尚未完成的回复。批量大小仍为最多 20 条，模型可以比较同批回复。首段数据需在 25 秒内返回，之后连续 15 秒没有新数据或总耗时达到 90 秒才会中止。服务需要支持 OpenAI 兼容的流式响应；若服务忽略流式参数、返回普通 JSON，仍按整批结果显示。

#### AI 判断出错时

开启评论 AI 判断后，帖子页标题栏会区分请求超时、输入内容过长、接口限流、鉴权失败、网络异常和扩展连接失效。点击错误提示可查看原因、处理建议和原始错误详情，并选择重试、打开 AI 设置或刷新页面。

`Extension context invalidated` 表示扩展与旧页面的连接失效，常见于扩展更新或重新加载之后。刷新当前 X 页面可重新建立连接；它不是 AI 上下文过长的提示。AI 请求按首段等待、数据中断和总耗时分别计时，只有服务明确报告上下文超限时，才提示输入内容过长。

#### 正文关键词过滤

#### 原创内容奖励计划

在弹窗里显示创作者奖励计划的曝光进度（过去 90 天累计的已验证首页时间线曝光 / 50 万）。

下方显示某一天的整体曝光、蓝 V 曝光（来自 X 账号分析）和计入奖励（按每日累计差值计算）。点近 7 天柱状图可切换日期，悬停蓝 V 曝光显示其占整体曝光的比例；悬停计入奖励显示其占整体曝光、占蓝 V 曝光的比例。奖励计划只给近 90 天累计数，插件每天北京时间 10:30 后记录，相邻两天相减得到净变化，其中包含到期移出与平台修正，不能当作当天新增的合格曝光。

点击「查看历史看板」在独立页面回看自然周、自然月、近 90 天或自选日期。默认显示本周周一到周日，今天及后续日期保留格子、数值留空；汇总只统计已结束的日期。一个月以内使用日历，每格显示日期和所选指标的当天数值；未结束日期置灰。90 天视图保留趋势图，可切换按天、按周汇总；完整时段与完整上一期可比较涨跌。缺失日期仍留空；汇总展示已记录日期的合计，并紧邻标注覆盖天数，不将缺失日期算成零。计入奖励为主要指标，曝光为辅助指标；日历通过短条长度和高值底色表示每天的大小，标记最高日。主看板采用紧凑布局，数据说明与每日明细默认收起。点击顶部「导出图片」后填写可选署名，将当前日历或趋势图导出为本地 PNG（图片文件），不会发布。

账号分析的本地缓存保留最近 120 条日记录，看板打开或刷新时按需请求 90 天历史；X 实际返回范围以页面记录天数为准。奖励历史只包含本机已记录的日期，无法用当前累计值补回过去每日数据。统计日沿用 UTC（协调世界时），对应北京时间当日 08:00 至次日 08:00。

#### 引用我的帖子

在发帖、引用和回复编辑器里多一个按钮，搜索自己发过的帖子和长文，点击结果把链接插入草稿，不用另开标签页去找。

- XChat 聊天输入框旁也有「引用我的帖子」图标；空输入框按 `/` 可打开同一个选择器。选中后在光标位置插入链接，保留其他文字，再按聊天原有方式发送。`Esc` 关闭选择器。

- 打开已登录的 X 后自动分批同步历史帖子（每批最多 20 页、每页间隔 2.5 秒，断点会保存，关掉页面下次打开接着同步），之后约每 30 分钟检查一次新帖。多个标签页共用一把同步锁，可以暂停和继续。
- 可以在「创作 → 引用我的帖子」关闭「打开 X 时自动同步」，关闭后已有缓存仍可搜索，也可以手动同步。
- 受 X 接口返回范围限制，不保证能拿到全部历史；本地副本可能保留已删除或修改前的内容。不会自动发帖。

#### 发帖列表

选中发帖、引用或回复编辑器中的文字，可以在原生加粗、斜体旁使用圆点列表和编号列表；底部工具栏也有相同入口。点击添加列表后保留选区并恢复原生工具栏，再次点击取消，无需重新选择文字。已应用的按钮会显示选中状态。

- 圆点列表使用 `• `，编号列表使用 `1. `、`2. ` 行首字符。按实际换行处理，忽略视觉折行，保留空行和缩进；未选文字时处理当前行。
- 圆点和编号列表可互相转换。全部选中行已有对应列表时再次点击取消，混合选区则补齐列表。
- 只修改列表前缀，保留正文原有的加粗、斜体和链接。

普通帖不提供引用段落、下划线和删除线按钮：字符模拟无法保证字体和线条效果，本机样式也不会随帖子保存。

#### 多图排版与排序

发帖时放 2 到 4 张图，图片排成两列等大的格子，按发帖顺序从左到右、从上到下排，右下角标出序号，横图、竖图都完整显示。按住一张图拖到别的格子，松手后顺序就改好了，发出去的帖子、定时帖和草稿都按新顺序，不用删掉重传。

- 只是点一下图片时，照常打开 X 的「编辑媒体」；拖动时按 Esc 可以取消。
- 改的是 X 发帖框自己记录的图片顺序，不拦截、不修改发帖请求。读不到 X 的数据时保持 X 原来的排版，拖动失败会提示。
- 有视频或 GIF 时保持 X 原样。不需要时在「创作 → 多图排版与排序」关掉。

#### 按名字艾特

X 的发帖框只认 @ 后面的英文字母、数字和下划线，在 @ 后面输入中文名不会列出账号。打开这个功能后，在发帖、引用和回复编辑器里，@ 后面输入中文、日文等非英文名字，光标下方会列出名字相符的账号，已关注的排在前面。用上下键或鼠标选一个，按回车、Tab 或点击，「@名字」换成「@用户名 」，X 按艾特处理。

- 查询用的是 X 发帖框自己的用户查询接口，输入的名字会发给 X。英文名 X 自己会列出候选，这个功能不处理。
- 只按对方在 X 上显示的名字查。简体和繁体分开查，对方名字写的是繁体时，用简体搜不到；对方名字是英文时，搜中文译名找不到。
- 用拼音等输入法时，选完字才查询。按 Esc 只关闭列表，发帖弹窗保留。不需要时在「创作 → 按名字艾特」关掉。

#### 右键存草稿

在任意网页选中一段文字，右键点「存为 X 草稿」，选中的文字存进 X 草稿箱，后面空一行附上这个网页的链接。存好后扩展图标上显示 ✓，3 秒后去掉。之后在 X 发帖框右上角的「草稿」里找到它。

- 用这个浏览器里已登录的 X 账号，调用 X 网页存草稿时用的接口，不需要打开 X 标签页。
- 存不进去时（没登录 X、接口变了等），在当前标签页旁边打开 X 发帖页，文字已填好；关掉发帖框时点「保存」，存进草稿箱。
- 只附 http 和 https 网页的链接；选中的文字里已经有这个链接时不再附。
- 只在点菜单项时读一次当前网页里选中的文字。不需要时在「创作 → 右键存草稿」关掉，菜单项随之去掉。

#### AI 总结转发

在发帖、引用和回复编辑器里，点「AI 总结」按钮，读取原帖全文，用你配置的模型生成两条草稿。按钮位于「每个人」右侧；回复弹窗和页内回复框没有受众按钮时，入口放在输入框上方。页内回复以当前详情页的帖子为原文。选一条填进编辑器，再自己修改。草稿按插件界面语言写：中文界面写中文，英文界面写英文。

- 支持 OpenAI 兼容接口。在「设置 → AI 服务」填写接口地址、API Key 和默认模型，点「授权并测试连接」。扩展只申请这个服务地址的访问权限，拒绝授权就不会发请求。总结转发和评论判断共用此服务，各自可以单独填写模型，留空则跟随默认模型；旧版连接配置会自动迁移。
- 默认生成「干货总结 - 详细」和「干货总结 - 简短」。四种预制风格还包括「话题延伸 - 详细／简短」。两个详细版沿用原版提示词与默认风格，不新增字数限制；简短版的要求只作用于简短选项。请求开头明确说明总结与文案创作任务，供意图路由与逐句翻译区分。简短总结提炼原文的一个核心结论或具体信息，要求 1—2 句、尽量 60 字以内，语气自然，可轻微俏皮；长度和相关性由提示词约束，发布前仍需检查。
- 在「模型与风格 → 风格管理」中新增、复制、编辑或删除自定义风格。每种风格单独设置名称、参考类型、写作要求与参考样本，编辑后点击「保存风格」。参考样本用单独一行 `---` 分隔，最多使用 5 条；只学习表达，不复制事实或经历。明确的自定义语气、结构与长度要求优先于参考类型的默认要求。
- 两条草稿可分别选择任一预制或自定义风格，选择自动保存并用于后续生成。删除正在使用的自定义风格时，对应草稿恢复默认项。预制项保留，可复制后修改；旧版「简短回复」选择自动对应「干货总结 - 简短」。
- 之前填写的风格描述和样本保留在「预制风格的通用偏好」中，仅作用于预制项；自定义风格使用自己的要求和样本。补充要求仍对本次生成的两条草稿共同生效。
- 生成时会把原文、作者信息、文章标题、转发风格和补充要求发给你配置的服务，连接测试只发送测试文本。总结生成等待完整结果，扩展不设置等待上限；点取消或关闭面板会中止请求，但服务商可能已经处理并计费。浏览器后台生命周期、网络和服务端仍可能中断请求。连接测试和原文补全仍保留 25 秒超时。远程服务必须用 HTTPS；HTTP 只能用于本机的 localhost 和 127.0.0.1（如本地反代、Ollama）。

### 05 互动与列表

#### 通知用户卡片

选择卡片模式后，进入通知页会先显示「正在整理通知」占位，再显示卡片，避免等待本地状态时先露出原始列表。加载期间仍可切换到原始列表；状态读取失败或超过 3 秒时恢复原始列表。

默认关闭，可在「互动 → 通知用户卡片」开启。开启后，通知页保留 X 的「全部 / 优先 / 提及」标签，增加「用户卡片 / 原始列表」切换。显示方式会保存在浏览器本地，刷新、重新进入通知页或重新开启功能时直接恢复上次选择，并在已打开的 X 标签页之间同步；两个筛选项分别保留。卡片按最近互动排序，点击后在当前行下方展开该用户的回复、提及、点赞、转帖和关注通知。字体、深浅主题和强调色跟随 X。关闭后，卡片、角标和模式切换栏全部隐藏，仅保留 X 原始通知列表；已有的手动开关设置会保留。

有回复／提及的卡片使用侧边强调线、类型图标和加粗标识，优先预览最新未查看回复；回复均已查看时展示最新回复。点赞、转帖、关注使用中性样式。卡片仍按最近互动排序，不再单独放大第一张卡片；窄屏使用单列。角标统计当前类型筛选范围内的未查看通知，统一使用主题色；类型标识只显示文字，不显示条数。新增点赞不会把已查看回复重新标新。

- 用户卡片模式提供「只看回复」和「仅未查看」两个独立复选框。首次使用时两项均不勾选，之后自动恢复上次选择；勾选「只看回复」后仅展示回复／提及，隐藏点赞、转帖、关注、新帖提醒和其他通知，取消后恢复全部类型。两项同时勾选时，只保留有未查看回复／提及的用户；新点赞不会使旧回复入选。展开卡片仅显示当前类型的记录，但会统一将点击时已加载的该用户互动标记为已查看，包括被筛选隐藏的点赞、转帖和关注。切换筛选不会让这些记录恢复未查看；其他用户和点击后新增的通知不受影响。两项选择分别保存在浏览器本地，刷新、重新进入通知页、切换账号或通知分类后均保留，并在已打开的 X 标签页之间同步；切回原始列表时隐藏筛选控件。
- 只整理当前通知标签里已经加载过的记录，最多保留 500 条在页面内存中；切换账号或通知标签后清空这一批记录。需要更多历史时，切回原始列表滚动加载，再切回卡片。
- 展开卡片后，可在回复／提及记录下点击「回复」。在当前标签页进入对应留言的帖子页，再定位到页面内的回复输入区，沿用 oh-my-x 的编辑器增强。原生节点被虚拟列表回收后也使用同一路径，不另开回复弹窗或标签页。为支持完整页面导航，目标帖子与账号会暂存在当前标签页，有效期 15 秒，定位完成后清除；不保存回复正文。点赞、关注等没有明确留言链接的通知不提供回复入口。
- 角标是插件自己的「未查看」记录，不同步 X 官方未读数。首次使用以当前时间建立基线，历史记录不标新；之后收到的新记录在展开对应用户卡片后按该用户点击时已加载的互动统一标记为已查看，不受类型筛选影响。多用户合并通知对每个用户分别记录查看状态。
- 开启此功能时，在「原始列表」点开通知也会保存已查看状态，切回卡片或从帖子页返回后同步清除对应角标。点开合并通知会标记其中所有可识别用户，不受卡片筛选影响；点开新帖提醒后，卡片中也会隐藏该提醒。仅点击头像、个人主页或点赞等操作按钮不会标记整条通知。旧版本未记录的点击无法补回，需要重新点开一次或使用「全部标为已读」。
- 点赞和转帖按「用户＋目标帖子＋互动类型」保存已读状态。合并通知新增参与者、更新时间或改写摘要，不会把已查看的其他参与者重新标为未查看。优先使用原帖地址；原生通知未提供地址时使用原帖正文摘要，没有两者时保留时间区分。相同正文摘要的不同帖子无法可靠区分。旧版收据在原始通知仍可匹配时自动迁移，已变更且无法匹配的旧记录不能反推，需重新查看一次。并发保存和跨标签页同步只合并已读记录，不用旧响应覆盖新状态。
- 同一条合并通知仍计为一条通知，只展示页面可识别的用户和已有摘要，不推算未提供的帖子或其他参与者。「最近互动」标题右侧提供「全部标为已读」，只处理当前筛选下已加载的互动，不处理新帖提醒；勾选「只看回复」时仅标记回复／提及。批量处理期间的新通知仍保持未查看。进入通知页或重新切回该标签页时，通过当前通知分类的原生入口刷新；提醒随 X 返回的原生列表更新。已打开小铃铛的账号的新帖提醒只缓存最新一条，且仅在未查看时展示。点击后隐藏，并按账号保存已查看提醒的时间；返回页面、取消「仅未查看」或加载更旧通知都不会恢复它，只有时间更新的未查看提醒才重新展示。新帖提醒在「最近互动」上方独立展示，标题行右侧显示时间与未查看状态，不显示固定数量；下方头像单行最多显示 7 个，超出用「+N」表示已识别用户的剩余数量；摘要与头像居中对齐，窄屏时摘要移到头像下方，查看入口独占下一行，不计入用户互动。点击整条新帖卡片直接触发 X 原生通知，进入新帖汇总页，不切换列表模式。提醒、用户卡片和详情中的头像均可独立进入个人主页；原生头像仍在页面时复用 X 悬停资料卡，保留简介、关注状态等原生内容。原生通知被回收时提示刷新后重试，不拼接缺少时间线状态的汇总页地址，也不提前标记已查看；头像的主页链接仍可使用。新帖提醒的隐藏不依赖「仅未查看」开关；其他系统通知仍放在「其他通知」。
- 查看基线、通知标识与用户的查看记录按登录账号保存在 `browser.storage.local`，最多保留 20 个账号、每个账号 2000 条查看记录。通知正文和头像地址只保留在当前页面内存，不新增通知接口请求。

#### 媒体下载

在推文的分享菜单里加入图片下载、MP4 下载和「导出 GIF」选项，样式和菜单里的其他选项一致。原有的「下载 GIF (MP4)」保存 MP4 文件；需要 `.gif` 文件时选择「导出 GIF」，扩展会在新标签页中转换，完成后可以预览，点击「复制 GIF（用于 X）」后直接在 X 发帖框粘贴，也可以点击「保存 GIF」。你自己发的视频，X 菜单里已有「下载视频」，这时不再重复加入 MP4 下载项。

- 转换在本机进行，不上传媒体；支持推文中的 GIF，也支持将短视频转成 GIF，默认取第一项 GIF，没有 GIF 时取第一项视频。
- 输出每秒 10 帧、长边最多 480 像素、最多 256 色，循环播放，不保留声音。小图不放大。
- 源媒体最长 60 秒、最大 50 MiB；生成文件最大 64 MiB。超限会提示改用 MP4 下载，不截断内容。
- 转换期间请保持导出页打开；可以取消或重新导出。
- 复制支持 15 MiB 以内的 GIF。粘贴到 X 时需启用 oh-my-x；扩展只处理本功能复制的 GIF，将完整动画还原为文件附件，不会自动发布。复制不申请剪贴板读取权限，也不保证其他应用支持此格式。

#### 收藏

- 左侧导航栏的 Home 上方加入「收藏」，点击展开收藏的博主，支持按昵称或用户名搜索，点击名称直接打开主页。

- 拖动博主左侧的手柄调整收藏顺序，松开后自动保存；也可聚焦手柄后使用上下方向键。搜索结果中调整顺序不会移除其他收藏。

- 收藏保存在当前浏览器，与 X 关注关系及 Lists 分开；在「互动 → 收藏」关闭功能后，已有收藏仍保留。

- 在设置里同步当前账号已有的 Lists，或通过链接、ID 手动添加。

## 设置弹窗与完整设置页

点浏览器工具栏里的 oh-my-x 图标打开设置弹窗（400 像素宽），按 6 个模块分标签（模块归属定义在 `shared/feature-registry.ts`）：

| 标签（模块） | 功能 |
|------|------|
| **界面**（界面与阅读） | 时间线宽度、右侧边栏、发帖按钮、导航栏按钮与文字、长文目录、搜索默认「最新」、搜索筛选条、问 Grok、AI 转搜索语法 |
| **过滤**（内容过滤） | 垃圾回复过滤（今日拦截、隐藏阈值、调试模式、9 条检测规则、垃圾词库）、正文关键词过滤与屏蔽词、账号例外（白名单 / 黑名单）、拦截记录 |
| **数据**（数据洞察） | 看板：原创内容奖励计划、博主活动度、粉丝与关注分析；页面标注：爆款雷达、数据比例徽章、用户粉丝数、收藏量 |
| **创作**（创作与发布） | 引用我的帖子、多图排版与排序、按名字艾特、右键存草稿、AI 总结转发、排期全景 |
| **互动**（互动与列表） | 快捷键与底部悬浮条、直达回复区、回复自动点赞、媒体下载、未互关标记、收藏、X Lists |
| **设置** | AI 服务配置 |

「过滤」页分两层：第一层显示每个功能的开关和当前状态，点卡片右下角的「详细设置」「管理屏蔽词」「管理名单」「全部记录」进入第二层，左上角返回。

**界面语言**：弹窗顶部（完整设置页在侧栏顶部）的地球图标按钮可以选「跟随浏览器」「中文」「English」。跟随浏览器时，浏览器语言以 zh 开头用中文，其他用英文。X 页面上已经显示的插件界面，要刷新页面后才换语言。

**完整设置页**：点弹窗右上角的「完整设置」按钮，会在新标签页整页打开设置，并定位到弹窗当前所在的模块；也可以在 `chrome://extensions` 的扩展详情里点「扩展程序选项」打开。设置页和弹窗内容相同、设置共用，适合编辑词库、名单和 AI 服务配置。地址末尾的 `#layout`、`#filter`、`#insight`、`#create`、`#engage`、`#settings` 对应六个模块。

## 隐私

- **本地保存**：设置、关键词、拦截日志及 AI API Key 保存在 `browser.storage.local`，帖子库和粉丝／关注名单保存在扩展本地 IndexedDB。API Key 未由扩展加密，界面遮罩仅用于隐藏显示。
- **X 请求**：帖子同步、Lists、用户指标、创作者奖励和互动辅助会使用已有登录会话与 X 通信。开发者不接收这些数据，也不收集遥测。
- **可选 AI 请求**：用户主动生成、测试或使用 AI 搜索时，以及在用户启用的评论 AI 判断范围内，向已授权的服务地址发送相应内容；该服务商的数据和计费条款适用。AI 请求不携带浏览器 Cookie。
- **权限**：使用 `storage`、`cookies`、`alarms`、`downloads`、`scripting`、`contextMenus`、`activeTab`（这两项用于右键存草稿：点菜单项后读一次当前网页选中的文字），以及 `offscreen`（在离屏页面运行本地图片文字识别）；默认主机权限限于 X 相关域名、`abs.twimg.com` 和 `video.twimg.com`（供 GIF 导出页读取媒体）。自定义 AI 主机通过可选权限按需授权；图片文字识别首次启用时另行申请图片和语言数据来源权限。可在 Chrome 扩展设置中管理。
- **脚本运行范围**：仅在 `twitter.com`、`mobile.twitter.com`、`x.com`、`pro.x.com` 注入页面脚本。

详见 [隐私政策](PRIVACY.md)。

## 开发

```bash
npm install
npm run dev        # 开发模式（HMR）
npm run build      # 生产构建
npm test           # 运行单元、DOM 与集成测试
npm run typecheck  # 检查 TypeScript 与 Vue 脚本、模板
npm run check      # 类型检查 + 全量测试 + 生产构建
npm run zip        # 构建 + 打包 ZIP
npm run clean      # 清理构建产物
```

通知卡片另有真实浏览器布局回归检查：`node scripts/test-notification-layout.mjs`。需要 Playwright Core 和 Chromium；也可通过 `NOTIFICATION_PLAYWRIGHT_MODULE`、`NOTIFICATION_CHROMIUM` 指向现有安装。测试使用合成通知，不需要登录 X，覆盖隐藏期间的行高、切换首帧、从主页进入通知、窗口缩放，进入帖子页后定位回复输入区，以及三种主题、三档宽度下的卡片层级、文字对比度和详情展开位置。截图输出到 `.metrics/notification-hierarchy/`。jsdom 不执行布局，不能替代这项检查。

GitHub Actions 会在 push、pull request 和手动触发时执行 `npm ci` 与 `npm run check`，通过后保存 Chrome 扩展构建产物 7 天。

**发布新版本**：先把 `package.json` 的 `version` 改成新版本号并提交，再推送同名标签（如 `git tag v2.0.0 && git push origin v2.0.0`）。`release.yml` 会检查标签与版本号一致，跑完 `npm run check` 后把 `oh-my-x-chrome-mv3.zip` 发到 Releases 页面。CI 使用 Node.js 24；本地建议使用 Node.js 24.15 或更新的 24.x。

界面文案在 `shared/i18n/zh-CN.ts` 和 `shared/i18n/en.ts`，规则见 [AGENT.md](AGENT.md) 的「界面语言」一节。
