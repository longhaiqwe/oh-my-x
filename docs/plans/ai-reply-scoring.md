# 回复区 AI 打分方案

状态：方案，未改代码。初稿 2026-10-18；2026-10-20 对照 [x-reply-guard](https://github.com/dontbesilent2025/x-reply-guard)（0.1.0，MIT）修订，对照结论见第 11 节。

## 1. 目标

在现有「评论垃圾过滤」上加一层模型打分。

- 每条回复得到一个 AI 嫌疑分（0–100），附命中的信号编号和一句理由。
- 分数 ≥ 阈值的回复折叠成一行，可以展开，不删除。
- 默认只在**自己帖子**的详情页自动判断；别人的帖子手动点按钮判断。
- 用户可以把一条回复标成「机器人」或「真人」，标注存在本地，可以导出。
- 规则过滤照旧，模型只处理规则没隐藏的回复。

这次不做：

| 不做 | 原因 |
|---|---|
| 三项分数（AI 概率 / 低信息量 / 引流） | 引流已有规则（`mention_referral`、垃圾词库）；低信息量和「万能回复」「复述原帖」两个信号重叠 |
| 第一版拦截接口取作者资料 | 先只用页面上能拿到的正文、handle、回复间隔，第 1 步之后再做对比实验 |
| 模拟点击 X 菜单拉黑、静音 | 有被 X 限制的风险，另议 |
| 结果出来前先隐藏 | 自动判断只在自己帖子下进行，等待 2 秒左右，先显示 |
| 对主帖打分 | 范围外 |

## 2. 现状

| 能力 | 位置 | 说明 |
|---|---|---|
| 对话页扫描 | `content-scripts/spam/scanner.ts` | 只扫详情页和 Deck 对话栏，主贴不评分 |
| 规则评分 | `shared/spam-rules.ts` | 规则分数相加，≥ 阈值（默认 55）隐藏 |
| 黑名单 / 白名单 | `content-scripts/spam/config.ts` | 黑名单强制隐藏，白名单放行 |
| 隐藏方式 | `content-scripts/spam/article-state.ts` | 正常模式 `display:none`，不留占位；调试模式只显示评分条 |
| 拦截日志 | `shared/spam-logger.ts` | 最近 50 条，加 30 天分类统计 |
| 调模型 | `shared/ai-request.ts`、`entrypoints/background.ts` | OpenAI 兼容接口；地址、key、模型由用户填；后台发请求；25 秒超时；要先授权接口域名；请求带 `locale` |
| 中英提示词 | `shared/ai-repost.ts` | 提示词按 `Record<Locale, …>` 分中英两版 |
| 正文提取 | `shared/parse-tweet.ts` | `collectVisibleText` 会把 emoji 图片的替代文字算进正文 |
| 登录账号 | `shared/own-posts.ts` | `getOwnHandle()` |

缺：扫描时取推文 ID、主帖滚出页面后的记忆、送模型打分、结果缓存、分数标签和折叠条、标注。

## 3. 整体流程

```
扫描到一条回复
  ├─ 黑名单 → 隐藏（现有）
  ├─ 白名单 / 自己的回复 / 已标「真人」 → 放行
  ├─ 规则分 ≥ 阈值 → 隐藏（现有）
  └─ 其余 → 取推文 ID
        ├─ 本页内存里有结果 → 直接用
        ├─ 后台缓存里有结果 → 用缓存，计入「复用」（任何对话页都查，不花额度）
        └─ 都没有
              ├─ 自己的帖子且自动判断开着 → 进队列：攒 2 秒或满 20 条 → 后台 → 模型
              └─ 别人的帖子 → 等用户点「判断本页回复」
                                              ↓
                                  写缓存 → 回到页面 → 显示分数标签
                                                      └─ ≥ 阈值 → 折叠
```

## 4. 各部分设计

### 4.1 推文 ID、主帖和回复间隔

- **推文 ID**：在 `shared/parse-tweet.ts` 加 `extractTweetId(article)`，从 `time` 元素外层的 `/status/` 链接取，排除引用推文。
- **回复间隔**：同样从 `time[datetime]` 取发布时间，算出回复比主帖晚多少秒，送给模型作为信号。
- **主帖记忆**：按详情页的推文 ID 记住主帖的 ID、正文、作者、发布时间，以及排在主帖上方的上级推文的 ID。主帖滚出页面后，仍然用记住的正文作为上下文。
- **现有扫描器可能有的问题**（读代码得出的推论，第 1 步在真实页面确认）：`findMainTweetIndex` 在主帖和回复框都不在页面上时返回 0，把页面上第一条推文当成主帖。这条推文不评分；如果原来被隐藏了，会被 `applyAllow` 重新显示。改法：主帖不在页面上时，按记住的主帖和上级推文 ID 判断，其余推文都算回复。
- **自己的帖子**：主帖作者等于 `getOwnHandle()`。

### 4.2 判断标准和提示词

提示词分两段：判断标准、输出格式。输出格式由插件固定追加在后面。提示词分中英两版，跟插件界面语言（和 `ai-repost.ts` 的做法一致），理由文字也用这个语言。

判断标准的起点（文字自己写，思路参考 x-reply-guard）：

| 编号 | 信号 | 强度 |
|---|---|---|
| S1 | 万能回复：没有接住原帖的具体内容，放到别的帖子下面也成立 | 强 |
| S2 | 复述原帖：换个说法重复原帖观点，没有新信息 | 强 |
| S3 | 结构整齐：几十字的回复也有总分总、排比，句子长短一致 | 中 |
| S4 | 「不是……而是……」这类翻转句 | 中 |
| S5 | 结尾一句总结，或拔高到「本质上」 | 中 |
| S6 | 结尾提问求回复 | 中 |
| S7 | 套话、翻译腔（中文和英文各列几个例子） | 中 |
| S8 | 祝福结尾，或几乎每句带 emoji | 弱 |
| S9 | 回复间隔很短，内容却很长 | 弱 |
| S10 | 同一批里多个账号句式几乎一样 | 弱 |

打分规则：强信号加 30–40，中信号加 15 左右，弱信号加 5–10；错别字、口语、具体个人经历、追问原帖细节的回复减分。只按证据打分，没有信号就给低分。观点偏激、语气差、外语不地道不算证据。

输入：

```json
{"parent":{"author":"…","text":"…"},"replies":[{"id":"…","author":"…","text":"…","delaySeconds":41}]}
```

输出：

```json
{"results":[{"id":"…","score":0,"signals":["S1"],"reason":"不超过 40 字，引用回复原词"}]}
```

- 正文截到 500 字。
- `temperature` 设为 0。服务支持 `response_format: json_object` 就带上；不支持就从返回文字里提取 JSON。
- 解析容错：缺 ID 的条目丢掉；分数四舍五入并截到 0–100；不在本批里的 ID 丢掉；整批解析失败按失败处理，同一条最多重试 2 次。
- 提示词带版本号 `PROMPT_VERSION`，改了提示词，旧缓存作废。

### 4.3 打分请求

- `AiRequest` 加 `XF_SCORE_REPLIES` 类型，带 `locale`。沿用现有机制：一次请求一个连接，页面关掉就取消，25 秒超时。
- 接口地址和 key 用 AI 转发的设置。另加「打分模型」设置，留空时用 AI 转发的模型。
- 后台另加一个只查缓存的消息 `XF_LOOKUP_REPLY_SCORES`，不调用模型。

### 4.4 缓存

- 存在后台的 IndexedDB（插件自己的数据库），不存 `storage.local`。原因：`storage.local` 每写一次，所有 X 标签页都会收到变更通知；x-reply-guard 把缓存放在 `storage.local`，每次读出整份缓存再整份写回，页面脚本还得专门过滤掉这类通知。
- 键：推文 ID。值：分数、信号、理由、模型名、提示词版本、时间。
- 保留 7 天，最多 5000 条，超出时删最旧的。
- 页面脚本另存一份在内存里，同一页面内不重复向后台查询。

### 4.5 待打分队列

新文件 `content-scripts/spam/ai-scorer.ts`。

- 去重：同一推文 ID 已在队列里或请求中，就不再加入。
- 攒批：自动模式攒 2 秒，或满 20 条就发。每次调用有固定开销，批次大一些更省额度。
- X 只渲染视口附近的推文，页面上有的回复就送，不另做视口判断。
- 同一页面同时只有 1 个请求。
- 每日上限只限自动判断，默认 300 条；手动判断不计入。
- 自动判断暂停时说明原因：没填 key、没授权接口域名、已达今日上限、已关闭、请求出错（附错误说明）。
- 切换页面时清空队列，并取消进行中的请求。

### 4.6 显示和折叠

- **分数标签**：打过分的回复，在操作栏（回复、转发、喜欢那一行）末尾显示「AI 82」。0–30 灰，31–69 黄，70–100 红。鼠标悬停显示理由和命中的信号名。
- **判断中**：已送出、还没返回的回复显示「判断中」。
- **折叠**：分数 ≥ 阈值（默认 70）的回复，隐藏原回复，在前面插一行：

  ```
  AI 82 · 万能回复、结尾提问 · @handle        展开   机器人   真人
  ```

- 点「展开」后，这条在本页内不再折叠（记在内存里）。
- **手动按钮**：别人帖子的详情页显示「判断本页回复」按钮，点一次送当前页面上还没打分的回复，最多 20 条；还有剩余时提示「再点一次继续」。
- 结果回来时，「结果版本号」加 1 并参与扫描指纹，然后触发一次扫描。现有扫描会跳过文本没变的推文，不加这一步，结果回来后不会生效。
- X 滚动时会重建推文的元素。结果按推文 ID 存，下次扫描时重新套用。
- 调试模式：评分条里加一行 AI 分和信号，不折叠。
- 标签、折叠条、按钮的选择器加进 `XF_SELF_SELECTOR`，插件自己插入的元素不触发扫描。

### 4.7 标注

- 入口：折叠条上的「机器人 / 真人」；没折叠的回复，在现有的选词、名单按钮旁边加一个标注按钮。
- 再点一次就撤销。
- 存在后台 IndexedDB：推文 ID、标注、正文、主帖正文、回复间隔、当时的分数和信号、模型名、提示词版本、时间。
- 标注后的效果：
  - 标「真人」：这条马上展开，以后不折叠。
  - 标「机器人」：这条马上折叠。
  - 不改模型给的分数。
  - 不自动改白名单、黑名单。
- 日志页加「导出标注」，导出 JSONL 文件（每行一条 JSON）。

### 4.8 样例集和提示词验证

- `test/samples/ai-reply-cases.json`：构造的回复样例，每条标好预期（`ai` / `human`），中英文都有，起步 20 条以上。
- 本地手动运行的验证脚本：读样例，用真实接口打分，列出每条的分数、预期是否相符、耗时、用量。key 从环境变量读，不写进任何文件。这个脚本不进 `npm run check`。
- 改提示词前后各跑一次，对比相符的条数。
- 用户导出的标注可以并入样例集。

### 4.9 日志和统计

- `SpamLogEntry` 加两个可选字段：`source: 'rule' | 'ai'`，以及 AI 分数和信号。旧记录没有这两个字段，照常显示。
- 每日统计：自动判断条数、手动判断条数、复用条数、失败条数、折叠条数。存 `storage.local`，后台每 5 秒合并写一次。
- 过滤页卡片的状态行显示「今日判断 N · 复用 N」。

### 4.10 设置界面

放在「过滤 → 评论垃圾过滤」的详细设置里，新加一节「AI 判断」：

| 设置 | 控件 | 默认 |
|---|---|---|
| AI 判断 | 开关 | 关 |
| 自动判断范围 | 分段：只我的帖子 / 所有对话页 / 不自动 | 只我的帖子 |
| 折叠阈值 | 滑块 0–100 | 70 |
| 打分模型 | 文本框，留空用 AI 转发的模型 | 空 |
| 每日自动上限 | 数字 | 300 |
| 今日统计 | 只读 | — |
| 导出标注 | 按钮 | — |

- 打开开关时检查：没填 key，提示去 AI 转发里填；没授权接口域名，在这次点击里请求授权（沿用 `requestAiPermission`，它必须在点击事件里同步调用）。
- 说明文字：「开启后，对话页的回复正文和作者用户名会发送到你填写的模型服务。」
- 新设置项按 `AGENT.md` 的规定处理：默认值写进 `storage-keys.ts`，归一化写进 `shared/settings.ts`，在 `shared/feature-registry.ts` 归到新功能 `spamAi`（父功能 `spamFilter`），中英文文案都要写。

## 6. 分三步做

| 步骤 | 内容 | 做完后能看到 |
|---|---|---|
| 1. 打分通路 | 推文 ID、主帖记忆和主帖识别修正、中英提示词、打分请求、解析、缓存、队列（只在自己帖子下自动）、样例集和验证脚本；只在调试模式显示分数 | 调试条上有分数和信号；验证脚本给出样例相符条数和用量 |
| 2. 显示和设置 | 分数标签、折叠条、手动按钮、查缓存显示、设置节、统计、日志、暂停原因 | 正常模式下显示分数，超过阈值折叠 |
| 3. 标注 | 标注按钮、存储、导出、并入样例集 | 能标注、撤销、导出 |

以后可选：拦截接口取作者资料（注册时间、粉丝数、简介）并用样例集对比准确率；用户自定义判断标准；把标注当示例放进提示词；在自己帖子下调用 X 原生的「隐藏回复」。

每步做完跑 `npm run check`（类型检查、测试、构建），再在内置浏览器里打开真实对话页检查。模型的 key 需要你自己在弹窗里填，我不能代填。

## 7. 测试

单测：

- 推文 ID、发布时间提取：引用推文、编辑过的推文
- 主帖记忆：主帖滚出页面、上级推文、Deck 对话栏
- 模型返回解析：不是 JSON、JSON 外面包着文字、缺 ID、ID 不在本批、分数越界
- 队列：去重、攒批、单请求、每日上限、手动不计数、切换页面后取消
- 缓存：过期、条数上限、提示词版本变化
- 判断顺序：黑名单、白名单、标注、规则、AI

集成测试：扫描器接一个假的打分服务，检查标签、折叠、展开、元素重建后重新套用结果。

弹窗英文测试（`test/unit/popup-english.test.ts`）要覆盖新的设置节。

## 8. 用量估算

x-reply-guard 说明文档里的实测（DeepSeek flash）：每次调用固定开销约 750 输入 token，每多一条回复约加 100；5 条回复约输出 350 token，即每条约 70。

按这组数字推算（未实测）：

- 每批 20 条：输入约 750 + 20 × 100 = 2750，输出约 20 × 70 = 1400。
- 每 1000 条回复：约 14 万输入、7 万输出。费用按所用模型的单价算。
- 默认每日自动上限 300 条，约 15 次调用。

第 1 步的验证脚本会记录实际用量，之后用实测数字替换这一节。

## 10. 风险

| 风险 | 处理 |
|---|---|
| 短回复误判 | 默认阈值 70；只折叠不删除；可以展开，可以标「真人」；用样例集检查提示词 |
| 主帖识别出错导致误放行或漏判 | 第 1 步先确认 4.1 的问题，加主帖记忆 |
| 折叠视口上方的回复导致页面跳动 | 沿用现有的 `overflow-anchor` 处理；自动判断只在自己帖子下进行，规模小 |
| 费用超出预期 | 默认只在自己帖子下自动；每日上限；缓存复用；第 1 步记录实际用量 |
| 隐私 | 默认关闭；开启处写明会发送哪些内容、发到哪里 |

## 11. 对照 x-reply-guard 的结论

| 项目 | x-reply-guard | 本方案 |
|---|---|---|
| 推文 ID、按 ID 重新挂标签、带主帖上下文、JSON 容错、7 天缓存、每日上限、失败重试 2 次、跳过自己的回复 | 有 | 一致 |
| 判断标准 | 10 个分强中弱的信号，返回信号编号 | 采纳思路，文字自己写（4.2） |
| 分数 | 一个 AI 嫌疑分 | 采纳，放弃三项分 |
| 自动判断范围 | 只在自己帖子下；别人帖子手动；其他页面只查缓存 | 采纳（4.5、4.6） |
| 回复间隔 | 送给模型 | 采纳（4.1） |
