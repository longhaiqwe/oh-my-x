# 粉丝与关注分析：实现与验证

北京时间 2026-11-11。基于已确认的第二版设计实现；截图均为实际组件使用合成名单渲染，不是用户的真实粉丝数据。

## 入口与行为

- 扩展「数据 → 看板 → 粉丝与关注分析」，默认关闭。完整设置详情地址为 `options.html#insight/audience`。
- 开启后，在 `/{handle}/followers`、`/{handle}/verified_followers` 与 `/{handle}/following` 页的原生标签栏下显示入口。认证粉丝独立保存，共同关注和推荐模块不进入名单。
- 只读取 X 自身发出的列表响应。没有自动滚动、额外 X 请求、取关操作或付费 API。
- 原始列表已加载、但监听尚未就绪的响应不补抓；界面提示继续滚动或刷新。分析窗口固定打开时的样本，关闭后重新打开才显示新增记录。
- 粉丝构成提供六档分布、三个累计门槛、搜索、分档筛选和每页 12 个账号。关注分析提供明确关系、账号属性筛选与两种排序。CSV 导出覆盖全部筛选结果。
- 缺失粉丝数不计为零，关系缺失不计为未关注；第三方关注名单不提供与登录账号的关系筛选。关注数为零时比值显示「—」。
- 本地名单按登录账号、目标账号、列表类型隔离。关闭采集后仍可查看、导出和清除；无 X 标签页也可读取。
- 每账号最多 3 个目标；每目标粉丝 2 万条、关注 1 万条；全库 10 万条或约 30 MiB 的 UTF-8 记录内容。达到上限停止新增，不驱逐旧名单。该字节数为估计内容大小，不是浏览器数据库实际占用。
- 跨天或间隔超过 24 小时停止合并；「开始新记录」需确认替换。清除递增账号代次，清除前的迟到写入不能恢复名单。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `shared/audience.ts` | 严格名单解析、字段校验、按字段时间合并、统计、筛选、CSV |
| `shared/audience-interceptor.ts` | MAIN world（页面脚本环境）旁路监听；请求发出时绑定路径、身份与采集代次 |
| `shared/audience-background.ts` | 后台消息来源、登录身份、路由、开关与字段校验 |
| `shared/audience-db.ts` | 扩展源 IndexedDB（浏览器本地数据库）事务、容量与清除 |
| `content-scripts/features/audience.ts` | 页面入口、生命周期、临时记录与采集队列 |
| `shared/components/AudiencePanel.vue` | 两类分析共用窗口、窄屏视图、筛选与分页 |
| `shared/audience-panel.ts` | 样式隔离、主题、模态背景、滚动恢复、Esc 与焦点循环 |
| `AudienceCard.vue` / `AudienceDetail.vue` | 设置卡片、本地名单管理、确认清除 |

列表响应可能不携带目标账号的 `rest_id`。解析器以已绑定页面上下文中的请求 `variables.userId` 为目标 ID；若响应同时给出 ID 或用户名，必须匹配。该兼容路径参考了公开的 [twitter-cli 测试样例](https://github.com/public-clis/twitter-cli/blob/main/tests/fixtures/followers_page.json)，并在本仓库使用自行构造的夹具验证。未把第三方样例或合成数据称为当前真实 X 响应。

## 2026-11-12 入口修复与认证名单补充

- 真实页面根因：入口插在 `ScrollSnap-SwipeableList` 内，父容器底部为 y=144，按钮从 y=144 开始，整条入口被 `overflow:hidden` 裁掉。现改为整个 `nav` 后的独立按钮，并在页面结构变化后重新定位。
- 标签切换根因：Chrome 的 `MessageSender.url` 保留原文档地址，X 使用 `pushState` 切换列表后仍按旧路径校验。后台现从浏览器读取发送方标签页的当前网址，并保留同源、账号、名单类型和用户名校验。
- 添加独立 `verified_followers` 名单，对应 `BlueVerifiedFollowers`；提供同样的分布、筛选和导出。认证名单不使用全部粉丝总数。每份认证名单上限 2 万人，仍计入原有全库限制。
- 旧设计与实现说明将认证名单列为不支持，README 和隐私说明只列两种名单。本次按用户要求更新这些说明，认证名单与普通名单不合并。
- 测试先复现入口裁切、认证响应被拒绝和切换后保存失败，再验证修复。25 项相关单元测试、类型检查和生产构建通过。完整扩展测试用合成数据验证三种名单、切换、裁切容器下入口、设置读取、清除后晚到响应和关闭采集。
- 北京时间 2026-11-12 10:26，在本机已加载的扩展上验证：普通粉丝入口显示 100 人；认证名单成功记录 40 人，并打开真实分析面板；切换正在关注显示原有 50 人。未清除用户名单。


## 2026-11-12 主题与字体校正

沿用 Vue、Tailwind 4、扩展主题变量与 X 原生字体读取工具。按照 Refactoring UI 检查本功能的入口、分析面板、本地名单及清除确认界面。

| 位置 | 问题 | 规则 | 调整 |
| --- | --- | --- | --- |
| 名单入口 | P1：整行文字同等突出，继承 body 字体 | §2.1、§4.1 | 人数 12/16、400；操作 14/20、600；字体从 X 标签文字读取 |
| 名单入口 | P1：默认蓝色焦点框与主题不一致 | §1.5、§8.1 | 当前主题色下划线、箭头和键盘焦点；鼠标点击不显示默认焦点框 |
| 分析面板 | P1：内边距、圆角及阴影有独立取值 | §3.2、§6.2.1 | 对齐 8/12/16/24 间距、12px 卡片圆角；使用现有阴影变量 |
| 设置中的面板 | P1：字体固定为 system-ui | §4.2 | 从设置页面读取实际字体；本地名单控件沿用主题圆角 |

入口高度 48px，窄屏可换行。面板主操作使用主题浅底和正文色，避免橙色底上的白色小字对比不足。数据采集、筛选和保存逻辑不变。

验证：回归夹具刻意让 body 使用衬线字体、标签使用 Arial；旧入口失败，新入口与原生标签字体一致，键盘焦点为橙色。8 种生产面板布局涵盖 1280px、375px、360px、深色、中英文与三种名单。真实 X 页面测得入口和原生标签字体相同，主题色均为 rgb(255, 122, 0)，入口高度 48px；面板正常打开。
